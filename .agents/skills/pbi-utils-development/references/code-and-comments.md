# 源码与注释

## 文件信息

新建完整源码、返回完整文件或修改缺头的源码时补充一次规范文件头. 保留已有作者、博客、版权年份/范围、第三方署名和许可; 只按实际情况更新路径与说明. 头部使用以下字段, 保持对齐:

```text
FilePath    : pbi-utils\相对路径
Author      : jiaopengzi
Blog        : https://jiaopengzi.com
Copyright   : Copyright (c) <新文件当前年份> by jiaopengzi, All Rights Reserved.
Description : 文件实际用途的中文说明.
```

- FilePath 包含项目根名, 不写本机绝对路径. 新文件使用生成时年份, 已有文件保留原年份. 不照搬示例占位符.
- C# 使用 `//`, 不把文件头写成 XML 文档注释. TypeScript/JavaScript/SCSS 用 `/** ... */`; Vue/HTML/XML 用 `<!-- ... -->`; PowerShell/YAML/Python 用 `#`.
- 保留 shebang、编码/XML 声明的位置; HTML 的 DOCTYPE 在文件头前. JSON 等不支持注释的格式不插入文件头, 不破坏格式.
- 局部 diff 或函数片段不重复文件头. Markdown 开发说明与 SKILL.md 不强行套源码文件头, SKILL.md 的 YAML frontmatter 必须保持首部有效.

## 文档注释

- 新增/修改后的函数、方法、组件写清用途、主要参数、返回值和可能错误, 使用语言规范的文档注释.
- 源码注释用中文, 标点使用英文, 逗号/分号后留空格, 中英文术语间适当留空格. 文件信息不能代替接口文档.
- 复杂逻辑说明决策原因、身份/并发/取消/提交边界, 不逐行复述实现. 抽离时等价迁移对应原注释; 若修正旧注释, 说明原因并保留其有效约束.
- 此规则适用于开发源码. 生成给用户的 M/DAX 关键注释按该功能的语言约定, 不据此改写用户已有源码、名称、字符串或注释.

## 实现约束

- 共享逻辑优先抽离复用, 同步说明调用方与行为影响. 不通过更改注释偷偷扩大业务重构.
- Nullable、CancellationToken、输入长度/类型、稳定错误及文化不变的机器格式沿用当前服务. 不吞异常、返回空成功、在 UI 同步等待或通过禁用 lint 规避问题.
- 不顺带升级工具链/依赖, 不批量格式化无关文件. 格式化写入与只读 check 分开执行.
- 检查字段实际路径、年份/署名、语法、语言、等价迁移及公开行为. 第三方源/资源保持许可信息, 不统一改为自有版权.

## C# 固定 DAX/M 模板

- 固定语法模板优先用原始字符串直接呈现生成代码: 无插值用 `"""..."""`, 插入已编码变量用 `$"""..."""`; M 列表/记录等包含字面花括号时可用 `$$"""..."""`, 以 `{{expression}}` 插值并保留单个花括号. 按内容选择单行或多行形式, 避免将完整固定模板拆成大量 `+` 与 `\n` 片段.
- 动态行、列、依赖闭包及流式内容继续使用现有 `string.Join`、`StringBuilder` 或结构化写入器. 固定外壳可改为原始字符串, 集合内容仍由原逻辑生成; 不把动态编译器机械改成一块大模板. 简短名称/路径拼接、协议规定的 CRLF 和已有 JSON/XML 序列化按其用途保持.
- 原始字符串只简化 C# 字面量, 不提供 DAX/M 编码. 参数与业务名称仍通过现有目标语言标识符/文本转义函数插入; 保留引号、方括号、M 的 `#` 转义和文化不变数字格式, 不直接插入未编码用户值.
- 保持生成内容的实际语义与字节约定: 核对关闭分隔符决定的缩进裁剪、插入多行片段、首尾换行、LF/CRLF、空白及引号. 保留既有 DAX/M 格式化入口, 不借格式化改写业务字符串内部的文本或元数据.
- 重构优先复用现有行为测试; 涉及长模板、嵌入片段或空白时, 对代表性输入采集改前/改后的实际生成输出并逐字符比较, 覆盖本次受影响的特殊名称、双语和文化环境. 只为未覆盖的真实边界补测试, 不用源码措辞或实现镜像断言代替输出验证.

## DAX 格式与命名

依据 SQLBI [DAX Format](https://docs.sqlbi.com/dax-style/dax-format) 与 [DAX Naming Conventions](https://docs.sqlbi.com/dax-style/dax-naming-conventions), 根 `AGENTS.md` 维护项目统一规则.

- 共享格式化支持 short/long, 默认 long, 编辑器通过 switch 显式选择. Long 在80字符内内联短调用与变量块; short 展开多参数和嵌套调用, 二元表达式按40字符子表达式布局. 四空格缩进, 函数调用与括号之间、非空括号内部留空格, 空参为 `BLANK ()`. SWITCH、ROW、ADDCOLUMNS 等按参数语义成对排版, CALCULATE/CALCULATETABLE 中关系筛选按上下文内联. 多行运算符置于续行行首, 比较右值及尾部标量不机械拆行; 逗号位于上一参数末尾. 表/列引用相邻, 命名空间点号两侧不留空格.
- 自有变量使用 PascalCase, 最后一个变量保存为 `Result`, 与现有模型表冲突时使用确定的 PascalCase 数字后缀. 完整度量定义头 `名称 =` 后换行; VAR 标量赋值可内联, 函数表达式与较长变量块按所选样式布局, 声明和 `RETURN` 之间不增加空行. 用真实 SQLBI API 双样式快照作为离线回归基准; API 仅用于开发期显式采集, 产品格式化不联网.
- 度量正文明确使用 `DaxFormatter.FormatMeasure`/`FormatMeasures`, 输出首个 LF 须在实际 TOM/TMDL 回读后仍存在, 顶级行顶格且只保留内部语法缩进; 完整定义头字符串的格式测试不能替代真实 body 通路. 查询、计算表及动态格式等其他槽位使用通用格式化. 已编码的单个常量可按相同正文布局直接包装, 保留生成器原有容量; 不改动常量内部的换行、引号与空白.
- 可见业务名称表达结果, 多词用空格、期间缩写作后缀; 已有公开对象名与报表引用保持. 自有 UDF 的函数名为 PascalCase, 模型相关函数用 `Local.` 等明确前缀、通用函数用库命名空间, 参数为 camelCase, EXPR 参数使用引用类型后缀. 外部库内容及精确引用不因样式改名.
- 词法格式化只调整布局, 不自动改变量名、表引号或表/列/度量绑定. 表名引号是否必要、列限定及去掉度量表限定须结合模型元数据验证; 不猜测 `[名称]` 的真实对象类型. 自有生成式应尽量显式提供正确列绑定, 保留目标语言安全转义.
- 重构自有表达式时保留字符串/注释原文、作用域、运算符和函数参数顺序; 变量重命名需核对完整作用域和冲突. 用实际输出与词元/变量等价验证, 以及既有行为测试覆盖边界; 格式化通过不代表引擎计算通过.
- 自动生成的 DAX 固定使用 Long, 不继承编辑器中用户显式选择的 Short. 固定后台查询由已核验、已转义的模型名称构造后使用 `DaxFormatter.FormatGeneratedQuery`, 复用同一 Long 排版但保留大模型查询容量; 此入口不接收网页自由表达式, 交互入口仍保留原字符与传输预算. 不通过对整串输出统一缩进而修改字符串或表名内部的实际换行.
- 排版扩张后仍须满足同一入口的单项、批量及 JSON 传输上限. 界面在回填前核验真实保存请求大小, 超限保留原草稿和整批预览; 不返回无法再次格式化或保存的部分内容.

## 前端目录与导入

- `use*` 组合式函数集中到 `web/src/composables/<原 src 领域>/`, 保留领域及子目录层级, 不与视图、文案字典、类型声明或纯工具混放. 不创建平铺聚合目录或保留旧路径转发文件.
- 国际化组合式入口是 `@/composables/i18n/useI18n`; 固定文案仍由 `web/src/i18n` 管理. 反馈与操作消息共享 `@/composables/ui/useFeedback`, 包括 `useOperationMessage`, 调用方导入真实所属模块.
- Vue API 和组合式函数使用显式且有类型的导入; 只在类型位置使用的依赖使用 `import type`. 不增加隐式全局、无类型状态袋或测试专用的产品导出.
- `*.test.ts` 移入 `web/tests/<原 src 领域>/`, 保持原领域与嵌套层级; 工具脚本测试统一放 `web/tests/tooling`, 全局初始化统一放 `web/tests/setup.ts`. 领域测试夹具、stub 与辅助模块随其测试领域组织, 共享支持文件放在测试目录内, 不进入产品 `src`.
- 测试通过现有 `@/` 别名引用产品源码, 测试内部支持文件使用相对路径. `@` 始终映射到 `web/src`, 产品源码不得反向依赖 `web/tests`.
- 迁移同步所有静态/动态导入、文件头 `FilePath`、源码读取路径、Vitest 的 `tests/**/*.test.ts` 与 `tests/setup.ts`, 以及 TypeScript 的 `tests/**/*.ts` include. 复核检查脚本、机器契约和相关文档引用, 保留现有严格选项与测试行为, 不用扩大扫描范围或弱化检查补偿漏改.

## 文件规模与拆分

- Vue 组件以约 300 行为可读性目标, C# 类和业务 TypeScript 参考同一原则, 不是强制阈值. 内聚解析器、声明表、生成代码和必要状态机可保留并记录理由, 不压缩排版或机械切片.
- Vue 按功能拆展示组件及有类型的 props/emits/model/slots, 复杂业务和共享状态用领域 composable, 页面仅组装. 不把整页搬入巨型 composable/状态袋, 不复制共享业务, 不添加当前无使用的配置或抽象.
- 保持原响应式依赖、草稿/选择、watch 时序、挂载/卸载、请求身份与迟到结果处理, 避免额外监听/请求/渲染. 抽组件须保留样式作用域、双语、ARIA、焦点/键盘、业务 disabled 与 guard.
- C# 以用例、策略、验证、存储和平台职责组织协作者, 保持公开签名和项目依赖. 共享同一私有状态/生命周期的 owner 可按职责使用 partial, 不能仅为缩短文件隐藏多职责. 资源、锁、授权、事务及提交后排空继续由权威 owner 管理.
- 原导出保持兼容或同步全部调用方及契约测试; 注释约束等价迁移. 先用现有行为测试固定基线, 再重构复验, 只补真实未覆盖边界, 不写实现镜像或行数测试. 验收层级按实际证据记录.
