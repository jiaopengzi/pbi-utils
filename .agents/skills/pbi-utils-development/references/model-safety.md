# 模型写入、保存与恢复

修改模型编辑、配置应用、MCP 工具、保存或恢复行为时，按本指南核对现有边界。普通保存直接执行，不提供保存确认偏好或长期模型历史备份；MCP 精确一次授权、独立风险确认和业务回执继续按各自用途执行。

## 来源与共享入口

- 只有宿主核实的本地 PBIP 和实际发现的 Power BI Desktop 模型允许编辑。Power BI Service、SSAS/XMLA 及其他远端来源保持只读；网页标记、模型回答或同名对象不能改变来源权限。
- UI、MCP 和模型配置复用 `src/PbiUtils.Application/Models/Editing/ModelEditService.cs` 的编辑门闩、草稿、验证及保存入口。不得绕过它直接操作当前模型，或为新入口复制一套弱化流程。
- 宿主绑定工作区、连接来源、文件身份和 Desktop 实例身份。Desktop 使用进程、启动时间、回环端点及实际文件关联复核；不能按名称、单个 PID 或网页路径猜测目标。目标变化后旧提案、快照、授权与保存票据不得移用。
- PBIP 文件编辑复用 `src/PbiUtils.Infrastructure/Projects/PbipModelEditing.cs` 与 `src/PbiUtils.Infrastructure/Projects/ChangeWorkspace.cs`；Desktop 适配复用 `src/PbiUtils.Windows/Models/Connected/DesktopModelEditing.cs`。业务层不依赖窗口句柄或 UI 自动化。

## 草稿、基线与事务恢复材料

1. 读取权威目标及完整基线. 连接 Desktop 的操作上下文独占绑定原引擎的 TOM 会话, 直接在原 Database/Model 对象上校验和本地暂存, 不创建私有校验模型克隆或复制完整候选. 原对象本地暂存不等于引擎提交; 失败、取消或确认拒绝结束本次事务与会话. 离线 PBIP 继续由文件事务私有 staging 准备. 预览和解析不得向引擎提交.
2. 用户发起的普通保存直接提交，不叠加通用保存确认。MCP 修改消费精确提案的一次授权；删除、覆盖或兼容级别升级等用例保留必要的独立风险确认。授权或确认等待不能放宽基线、目标或提交时限检查。
3. 提交前重新核实目标、完整基线、冻结摘要、资源来源与生成归属。外部修改、未应用 Power Query 更改或已有待保存状态必须按现有错误路径处理，不能覆盖或再次叠加同一操作。
4. 不创建首次定义或每轮提交的长期模型历史备份。事务临时回滚材料按本轮准确原状生成，仅用于本轮失败恢复；未知提交保留核验材料与业务回执，结果未定前不得清理。结果确定且恢复完成后清理临时材料，清理失败如实报告，不能把残留材料当作模型历史功能。
5. 离线 PBIP/TMDL 直接更新当前工程，通过私有 staging、基线复核、必要的临时回滚材料、原子替换及完整回读发布。失败恢复只处理本轮拥有的内容，外部并发更改不能被回滚覆盖。
6. Desktop 的原写会话已含本地暂存, 不能 Refresh 后重放操作或重生成 lineage. 提交前必须通过独立只读连接重新核实原权威身份与完整基线; 最终复核前在原事务取得数据库 CommitShared 锁, 持有至本事务 Commit/Rollback, 防止最后核验后的外部写覆盖. 锁获取异常或 XMLA 返回错误均拒绝提交, 不降级为无锁写入. 持锁完成独立权威复核后再对原对象一次 SaveChanges/Update 和事务 Commit. 提交开始后取得确定结果和独立完整回读事实, 再更新宿主基线. 未知提交不能靠重试同一操作判定结果.

除用户已明确授权的模板度量配置外, 生成归属必须按实际内容验证。模板度量及其参数对象在本次显式请求内按名称创建或原位置覆盖, 不受旧标记或人工编辑阻挡; 其模型目标、完整基线、必要事务恢复材料、一次提交和权威回读保持。其他未知、人工改动或归属失效的对象及资产不得当成工具生成内容覆盖。日期编号显式切换时可覆盖归属有效的标准生成列名和 SourceColumn，保留原列对象、业务别名及可核实引用；不能仅用对象名称或表列形状证明可覆盖。

## 完整 TOM 定义与当前生成归属

- 工作区基线、归属及配置保存回读采用 SDK 可写定义。`src/PbiUtils.Infrastructure/Models/Configuration/ModelConfigurationOwnership.cs` 仅通过 SDK 明确排除推导属性、推导对象和时间；lineage、表达式、分区、命名表达式、业务注解及锁仍属于完整核验内容。
- `src/PbiUtils.Infrastructure/Models/Configuration/ModelConfigurationReadback.cs` 对兼容级别与完整模型定义生成指纹，并在文件解析前后复核同一基线。网页 `ModelInfo` 是展示 DTO，不能代替完整 TOM 指纹；已经通过完整定义核验的配置，也不能因 RowNumber 等展示差异被误判失败。
- 新生成对象在打归属 stamp 前固定确定性 lineage 和适用的导入类型注解，不能在提交后忽略这些变化来追认成功。
- 仅接受当前 v2 完整定义归属，不保留旧 v1 stamp、lineage 补全或 live/file 对齐升级。旧格式、归属失效或人工变化的对象不能自动认领；lineage、表达式和业务注解变化仍须完整核验。

## 三阶段保存与只补保存

`ModelSaveResult` 的 `ModelSaved`、`FileSaved`、`DesktopSynchronized` 分别表达模型提交、文件持久化、对应 Desktop 同步的实际事实。按目标适用性解释各项；未打开 Desktop 的离线 PBIP 不得伪造 Desktop 已同步。

已连接 Desktop 的当前模型编辑统一直接提交原引擎, 日期与时间智能不例外. 原对象校验和本地暂存、独立身份和完整基线复核后仅调用一次 TOM SaveChanges; 经独立批准的兼容升级使用原 Database.Update, 同一事务 Commit 后独立完整回读确认. 不创建另一 TOM 操作模型, 不复制完整候选或重放已校验操作, 不创建长期模型历史备份. 成功返回 ModelSaved=true、FileSaved=false, DesktopSynchronized 表示对应 Desktop 引擎定义已完整回读, 不表示已观察窗口渲染. PBIP/PBIX 文件由用户在 Desktop 保存; 不使用文件先写/重载/自动文件保存流程, 不因手动文件尚未保存锁住下一次模型编辑. 新增日期表及数据定义改变后提示用户在 Desktop 显式刷新该日期表, 不发送 processing commands.

连接模型提交前失败结束原对象操作事务和会话, 保留用户表单输入. 提交开始后结果未知仍阻止写入, 核对后“重新读取模型”回读真实目标, 不重放原操作. UI 与 MCP 执行回执均按实际目标适用阶段判断完成, 不能将手动文件保存误记为 pending_save. 以下文件保存尾部和恢复约定仅适用于当前离线文件事务, 不保留旧连接模型文件尾部兼容恢复, 也不接入当前连接模型 CRUD.

- TOM 提交、文件写入、Desktop 重载/保存分别核验，不能把点击按钮、发出按键或 SDK 返回当成所有阶段完成。保存与 UI 同步不重新查询数据源；检查 SDK 元数据的 `Refresh` 不等于刷新模型数据。
- Desktop 配置落盘以完整文件 TOM 指纹证明；手动保存后的 PBIP 尾部还需同一进程、启动时间、文件路径及稳定官方 clean 状态共同证明。PBIX 不解析二进制，不能照搬 PBIP 指纹证明，也不能只凭 clean 推断其内容。
- 模型已提交但文件保存或同步失败时，保留部分成功及待完成状态；不能重新保留成可重复提交的模型草稿。重试通过 `IModelSaveCompletion` / `CompleteSaveAsync` 只完成保存与同步尾部，并先核实当前基线等于已提交基线。
- 用户已手动保存时，先按 `src/PbiUtils.Windows/Desktop/Files/DesktopFileSaveRecovery.cs` 做有界只读确认。通过后完成原回执，不能再执行模型修改。
- 保存控件失效只允许有界、只读重扫，每次重核实例身份。`src/PbiUtils.Windows/Desktop/Files/DesktopSaveControlLookup.cs` 的一次 Invoke 结果未知时只观察完成事实，不能重放该未知动作。
- 完整成功只反馈一次；部分保存、待核验与恢复入口持续表达真实状态，不得被普通完成消息覆盖。

## MCP 精确写入授权与执行回执

MCP 默认只读。模型工具只能提出当前白名单内的变更，不能把模型输出、网页批准字段、提案摘要、路径或保存偏好当作写权限。

- `src/PbiUtils.Application/Models/Editing/ToolWriteAuthorization.cs` 根据原对象校验和本地暂存前后的实际结果生成准确 before/after 提案; 宿主对已通过启动写权限和本机身份核验的 MCP 请求自动签发 `ToolWriteGrant`. 确认前不向引擎提交, 拒绝或取消须结束原操作会话. grant 只能消费一次, 并绑定运行、工作区、来源、完整基线和精确请求摘要; 过期或任一身份变化均拒绝.
- 普通保存没有额外确认或确认偏好。MCP 精确提案由宿主自动签发并消费一次授权，无二次弹窗；启动写权限、精确摘要、目标和完整基线核验仍强制执行。独立风险确认按各用例保留。
- MCP 副作用前必须具备可用的独立回执存储. `src/PbiUtils.Infrastructure/Execution/ExecutionJournal.cs` 保存宿主业务事实; 外部模型总结、工具响应或客户端历史不能取代回执. 提交开始前可靠记录边界, 结果确定后记录真实终态, 未知提交阻止新写和用户数据重置.

| 回执状态 | 必须保持的语义 |
| --- | --- |
| `prepared` | 准备记录已持久化，尚未开始模型提交；记录失败不得进入业务提交。 |
| `commit_started` | 精确授权后的提交边界记录已持久化；中断后不能假设未提交。 |
| `completed` | 依据实际保存结果记录完成，保留三阶段各自事实。 |
| `pending_save` | 模型已提交，文件或同步尾部待完成；只补保存，不重做模型操作。 |
| `needs_verification` | 提交结果未知，或重启读取到中断的 `commit_started`；阻止新的模型副作用。 |
| `not_committed` | 有确定依据证明未开始提交，不能用于掩盖未知提交。 |

回执先于工具最终响应持久化. 提交后的回读与回执不使用已取消的调用方令牌; 取消或客户端断开不能丢失已提交事实. 未知提交不能自动重放, 也不能用新的请求身份绕过. 完成回执不能被迟到失败覆盖.

## 并发、取消、关闭与恢复

- 同一目标编辑串行；未保存草稿、部分保存和待核验状态阻止切换或再次叠加写入。新建后配置当前同一文件时复用原编辑与保存服务，不能另建服务绕过这些状态。
- 提交前取消必须传播并等待原请求终结, 结束本次原对象事务和会话并释放准备资源; 同步 SDK 清理在线程池执行并等待完成, 接受取消不代表原操作已经结束. 进入提交边界后排空保存、回读及回执, 不把已经提交的操作报告成取消.
- 自动代码预览使用独立只读队列, 从绑定原目标的只读上下文核实完整基线并规划代码, 不建立私有校验模型克隆, 不修改原对象或向引擎提交, 不占模型写门闩. 过期或无效预览立即禁止复制旧代码; 偏好和纯解析队列不能授予写权限.
- 关闭先停止接收、取消适用的准备请求和活动对话框、撤销文档身份，再等待模型操作、预览、解析及脚手架队列排空，最后释放资源。沿用 `src/PbiUtils.Host/Bridge/Session/BridgeSession.cs` 的唯一终态和延迟释放逻辑，不靠提前销毁服务或结束外部进程完成关闭。
- 恢复先核实当前目标、实际模型、文件、完整基线、本轮事务恢复材料与回执。离线文件事务已提交则只补未完成阶段；连接模型结果未知则保留待核验并只读核对。不得重放已提交或可能已提交的修改，也不得用新运行身份、清空回执或回滚材料绕过未知状态。
- 放弃草稿通过现有恢复入口先成功回读权威源，再解除对应草稿状态；回读失败保留原状态。不能把放弃内存草稿解释为回滚已经发生的外部提交。
